# Scoped private biometric sample deletion

The supported enrollment process accepts three additional actions within its existing configured tenant/application scope. Set `deletion_authority_id` in the private configuration to an operator-reviewed delegation for confirmed deletion. Enrollment identity review or a Contacts link alone does not grant deletion authority. Missing authority returns an unavailable preview. Source qualification uses synthetic temporary data; no live/private corpus deletion has been qualified by these tests.

`deletion_preview` takes `sample_ids` (1–256 distinct curated Speech sample IDs). It returns `available`, optional `reason`, immutable `fingerprint`, `samples` mappings to exact upstream sample IDs/hashes, all affected immutable `profiles`, relevant unsettled `operations`, and `deleted_object_hashes`. It includes retained copies from failed jobs when their persisted sample manifest proves exact ownership. Original recordings remain outside this operation.

`deletion_apply` takes the same `sample_ids`, exact preview `fingerprint`, unique `operation_id`, and `approve: true`. The caller must persist its confirmed intent and prohibit new access/selection before calling. The bridge persists its own intent and sample/hash fences before any filesystem or custody effects. Changed intent or application reuse of an operation ID conflicts; stale preview and unsettled enrollment operations block effects.

The native A3 ledger retains its existing schema and single-sample behavior. An additive resolver computes the exact union of selected samples, dependent immutable profile versions and private objects. Its envelope uses existing target type `sample`, target ID `sample-set:<digest>`, schema `transcribe-audio.biometric-custody-sample-set-effect.v1`, and the explicit selected upstream `sample_ids`. Native A3 quarantine, sample deletion/profile invalidation events, effect receipt and tombstone remain authoritative. This avoids sequentially deleting the same shared profile object twice. Previously deleted shared objects are omitted only with an existing tombstone and verified absence from quarantine.

Responses contain `operation_id`, `sample_ids`, `fingerprint`, `profiles`, and status `pending`, `unknown` or `applied`. Only `applied` has `private_cleanup_verified: true`; it includes native `tombstone_id` when registered custody objects were affected. A failed job's pre-registration orphan copies can be removed under the durable, approved deletion intent, using only its exact persisted object IDs, content hashes and ordinary single-link files. Such orphan-only cleanup has no native custody tombstone and returns `tombstone_id: null`.

`deletion_status` takes the exact `operation_id`; absent intent returns `not_found`. It reconciles a committed native receipt and exact quarantine/object cleanup without reapplying native effects. It may finish orphan-only cleanup from the persisted approved intent. An interruption without a native receipt for an expected registered effect stays `unknown`; never retry with a new operation ID or automatically replay the effect. Unknown/pending fences remain held. All historical metadata and native tombstones survive byte deletion. Enrollment and comparison reject pending/deleted sample hashes or curated IDs, including old active profiles.

CLI launch, private configuration, parent-death guard and genuine adapter registry remain those in [speaker enrollment process](speaker-enrollment-process.md). The new actions perform no embedding, enrollment or automatic identity assignment. Speech's local coordinator separately owns sample payload removal, clone versions, comparison quiescence, consumer access and explicit browser confirmation.
